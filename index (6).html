Refresh Signal: Predicting Content Decline from Trailing Search Behavior

Abstract Which of a client's existing pages are worth reviewing for refresh, before their decline becomes obvious in a monthly report? We build a leakage-safe classifier that predicts content-level decline over a forward 30-day window (last30), using only pre-label-period signal: trailing GSC/GA4 performance, prior-30-day query behavior (prev30), and static content metadata. On a client-grouped held-out test set, the model reaches a Precision@50 of MODEL P@50, against a Week-4 rule baseline of BASELINE P@50. The result is directional and decision-support only — it flags association, not a mechanism, and makes no claim about Google's ranking algorithm.

Introduction

A content team managing hundreds or thousands of pages can't manually re-check every one each month. The decision this work supports is narrow and practical: given everything knowable about a page up to a point in time, which pages deserve a human look this week — and why — before the decline shows up in a client's own monthly report.

This sits in the Refresh / Content Opportunity Scoring lane: score pages that are growing, declining, recovering, or worth review, and output a ranked action list with a reason attached to each item, not just a bare score.

Data

FlyRank internship warehouse, release RELEASE VERSION. Four tables, joined at the client_hash_id / content_hash_id grain:

  • dim_clients — filtered to clients with genuine gsc_and_ga4 access.
  • dim_content — filtered to published, non-deleted content created before the analysis window started, so a "declined" label is even meaningful for that item.
  • fact_content_daily_performance — trailing daily GSC/GA4 signal, used only for dates strictly before the window began.
  • fact_content_query_90d — the source of the label: pre-computed last30/prev30 impressions, clicks, and average position per query, aggregated to content level.

Excluded, and why: content created after the window started (no trailing history to score); content updated or re-optimized during the window itself (a real intervention would be mixed into what's meant to be an organic-decline label); clients without full GSC+GA4 access (label would be built on incomplete signal). No client names, domains, raw URLs, or query strings appear anywhere in this paper — only the dataset's own pseudonymous hashes.

Methodology

Label

is_declining = 1 when average position worsened by at least POSITION_WORSENING_THRESHOLD and either impressions or clicks dropped by at least the configured threshold, comparing last30 to prev30. Both conditions are required so a single noisy metric can't flip the label on its own.

Features

Trailing daily performance (pre-window), prev30 query-level aggregates, and static content metadata (search volume, competition, CPC, backlinks, word count, category count, intent). Query-diversity features are derived from prev30 rows only — the warehouse's own full-90-day diversity columns span the label window and were confirmed, not assumed, to leak: training the same model with and without them produced an inflated Precision@50 on the leaky version. See Results.

Split

Grouped by client_hash_id (not time-aware — the release has one fixed window, so client-level correlation, not date order, is the real leakage risk). Every client's content sits entirely in train or entirely in test.

Model

Logistic regression, class_weight="balanced". Chosen for interpretable coefficients (each flagged item gets a reason code, not just a score) and because the dataset size after aggregation doesn't warrant more model complexity than that.

Limitations & Honest Framing

  • Directional, not causal. This flags association between pre-label signal and a forward outcome. It does not explain why a page declined, and it makes no claim about Google's ranking algorithm.
  • Single-window snapshot. One fixed window_start/window_end, not a rolling monitor. A production version would need re-validation each time it's re-run.
  • Click sparsity at content grain. Many query-level rows have zero clicks; the label leans on impressions drop as the primary volume signal, clicks as secondary.
  • New content is out of scope. Items created after the window started are excluded entirely — this model only scores existing content with trailing history.
  • Threshold choices are judgment calls, stated explicitly in the notebook, not tuned to produce a flattering number.
